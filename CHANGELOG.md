# CHANGELOG

This is the history of changes of the Route4Me Java SDK (`io.github.route4me:route4me-java-sdk`).

> Please follow this [guide](https://keepachangelog.com/en/1.0.0/).

## [2.0.0] - Unreleased

This is a major release: it removes and changes public API (see **Breaking changes**). The SDK still targets **Java 8**: the jar is built with `--release 8` and runs unchanged on Java 11, 17, 21 and later. CI tests it on JDK 8, 11, 17 and 21.

This release fixes every open bug report (#16–#19, #31–#41), adds 27 managers and 247 API methods for the operations the coverage issues list (#42–#104), and hardens how the SDK handles the API key. It also adds an offline test suite of 871 tests behind a request guard, and Javadoc for the whole public API. Several fixes change behaviour that code may rely on, so read **Breaking changes** before upgrading.

### Breaking changes

**Source and binary compatibility**
- **The SDK enums are immutable.** `setValue()` is removed from every enum, and their value fields are final (#40). No SDK code called the setters.
- `Constants.AlgorithmType`, `TypeofMatrix` and `DirectionsMethod`: `toString()` returns the API value (for example `"1"` instead of `"TSP"`), like the other `Constants` enums, and Gson writes that value. Use `name()` for the constant name.
- **The examples are no longer in the jar.** The 1.16.x jars shipped them as public classes in `com.route4me.sdk.examples` (and the 1.16.x pom brought OpenCSV for them). They now live in `src/examples/java`; see **Examples**.
- **`setGPS` returns the new `SetGpsResponse`** instead of `void` (#39). Callers compile unchanged but must be recompiled: the change is binary-incompatible. An answer that is not JSON, as the `csv`, `serialized` and `xml` formats of `GPSPosition` give, does not fail the call after the position is stored: its text is in `SetGpsResponse.getAnswerText()`, and the status and transaction ID are `null`.
- **The public static `GeocoderWebSockets.geocoderWebSocket` is removed.** Each `GeocoderWebSockets` now has its own socket, so two geocoders no longer share, and close, one connection.
- `OrderFilter` is now public, with chained setters. Its field `scheduled_for_YYMMDD` is renamed `scheduledForYYMMDD`, so the accessors change.
- `ThreadBasedGeocoding` implements `Callable<Address>` instead of the raw `Callable`, and its `call()` no longer declares `throws Exception`. Callers compile unchanged unless they catch a checked exception around `call()` or override it.
- `Route.isUnrouted` and `Parameters.useMixedPickupDeliveryDemands` start as `null` and are sent only when set. The old accessors keep their signatures and return `false` when unset; new accessors `getUnrouted()`/`setUnrouted(Boolean)` and `getUseMixedPickupDeliveryDemands()`/`setUseMixedPickupDeliveryDemands(Boolean)` expose the three states.
- `Vehicles.isOperational` and `isDeleted` (the deprecated `VehiclesManager`) also start as `null` and are sent only when set; `newVehicle` and `updateVehicle` always sent `is_operational=false` and `is_deleted=false`. The old accessors keep their signatures and return `false` when unset; new `getOperational()`/`setOperational(Boolean)` and `getDeleted()`/`setDeleted(Boolean)` expose the three states.

**Transport**
- **Requests time out.** Connect and connection-request timeouts are 6,050 ms and the read timeout is 30,000 ms (`Manager.DEFAULT_CONNECT_TIMEOUT_MS`, `DEFAULT_SOCKET_TIMEOUT_MS`, `DEFAULT_CONNECTION_REQUEST_TIMEOUT_MS`, each with a getter and setter). Before, a stuck call hung forever.
- **`Manager` implements `Closeable`** and keeps one pooled HTTP client per instance. Reuse managers and `close()` them; a manager used after `close()` builds a new client. The pool grows to the thread count of a bulk geocode. A request still running when another thread calls `close()` fails with an `APIException` ("the manager was closed while the request ran"), not with the unchecked `IllegalStateException` of the closed pool.
- **API V5 requests send the key as `Authorization: Bearer <key>`** instead of the `api_key` query parameter, so the key no longer appears in URLs, proxy logs or server logs. V4 requests are unchanged.
- **API V5 requests send `Accept: application/json, */*;q=0.8`.** Without it, API V5 answered errors with an HTML page, so their messages were lost. File exports still work.
- **Redirects are followed only over https to the Route4Me API hosts**, `api.route4me.com` and `wh.route4me.com`. Any other redirect fails with an `APIException` caused by a `RedirectException` (new class `http.Route4MeRedirectStrategy`).
- **Query booleans are sent as `1` and `0`.** `false` was sent as the text `"false"`, which PHP reads as true; `getTerritory` sent its `orders` and `addresses` flags the same way.
- **API V5 list and map query values use bracketed keys**, for example `ids[]=1&ids[]=2` and `filters[status]=1` (`QueryConverter.toBracketedParameters`). PHP keeps only the last value of a repeated plain key.
- IDs in URL paths are percent-encoded. A `null`, empty, `.` or `..` ID, or one that contains `/` or `\`, throws `IllegalArgumentException` before any request: some front ends decode `%2F` and `%5C` before they resolve `..`, so an encoded slash could still send the request, with the API key, to another endpoint.
- JSON bodies are sent as `application/json; charset=UTF-8`, form bodies as UTF-8 (they were ISO-8859-1), and requests without a body send no `Content-Type`. Responses are decoded with their declared charset, or UTF-8 when they declare none, or an unknown or illegal one.
- The caller's `URIBuilder` is no longer modified: `makeRequest` and `makeJSONRequest` add `redirect`, `optimized_callback_url`, `api_key` and the request object's query parameters to a copy, so a retry with the same builder does not repeat them. A response without a body (204) parses to `null`, or `""` for `String` and an empty array for `byte[]`. A reply larger than the manager's maximum response size (`setMaxResponseSize`) fails with an `APIException`.

**Errors**
- `APIException` carries the HTTP status (`getStatusCode`, 0 when there was no response), the body cut to 2,000 characters (`getResponseBody`), the parsed `errors`, V5 `error`, `code` and `messages` (`getErrors`, `getCode`, `getMessages`), the method and the URL with credentials redacted (`getMethod`, `getUrl`). `APIException(Exception)` keeps the cause (#19).
- `getErrors()` and `getMessages()` keep at most 50 entries from the body, each cut to 300 characters. `APIException.forIOException` throws `NullPointerException` for a `null` cause.
- Its message formats changed: "Invalid status code N for METHOD URL: first error"; "Unexpected server response for ...: the body is not valid JSON for X"; "METHOD URL failed: reason".
- The two `Manager.makeJSONRequest(method, builder, body, requestParams, ...)` overloads throw `APIException` when `requestParams` cannot be converted to query parameters, as the other two did; they logged the error and sent the request without its query.

**Manager methods**
- `updateTerritory` and `updateAvoidanceZone` send PUT with `territory_id` (#31), and reject a `null` territory, or one without `territory_id`, with `IllegalArgumentException` before sending: they threw a `NullPointerException` for a `null` territory, and sent PUT without the ID the API requires. `getTerritory` leaves out `null` flags.
- `updateOptimization` puts `optimization_problem_id`, `reoptimize` and `show_directions` in the query; `reOptimizationByOptimizationID` sends no body.
- `deleteRoutes` joins the IDs without a trailing comma (#41); with no IDs, or a `null` or empty ID, or an ID that contains a comma (which the API would read as several routes), it throws `IllegalArgumentException`. `mergeRoutes` refuses an ID with a comma too.
- `getOrders` with a filter sends POST with a JSON body; without a filter, or with a `null` request, it sends GET as before. `OrderRequest` fields and `DisplayType` constants serialise with their API names (#34).
- Geocoding (#32): `bulkGeocoder` returns one result per input, in input order, and no longer drops unmatched addresses. It enforces a deadline of `maxTimeout` per round of `maxThreads` addresses; the default `maxTimeout` goes from 500 to 30,000 ms (`GeocoderOptions.DEFAULT_MAX_TIMEOUT_MS`), since the old value never applied. `maxRetries` is the number of attempts, and 0 means one attempt.
- Null handling (#35, #36): `logActivity` throws `APIException` on an empty answer or a missing status; the `insertBreak*` methods throw `IllegalArgumentException` for a `null` amount or no route IDs; the `delete*` methods return `false` on an empty answer; several list getters return `null` on an empty body.
- `getContact` sends the plain ID (#33) and returns `null` when nothing matches. `getContact` and the deprecated `getContacts` reject a `null` ID or request with `IllegalArgumentException` before sending; they threw a `NullPointerException`.
- In classes of 1.16.1:
  - `Activity` reads `route_destination_id` (it mapped the typo `route_destination_od`), and `ActivityRequest` sends its type filter as `activity_type`, as C#, PHP and Node do (it sent `type`).
  - **`Order.getCustomUserFields()` returns `List<OrderCustomUserField>`** (it was typed with the package-private `OrderCustomUserFields`, which code outside the package could not use; that class is removed, and `OrderCustomFieldTypeInfo` is now public).
  - `RouteBreaksManager` rejects a `null` break duration, and `DynamicInsertManager` a `null` latitude or longitude, with `IllegalArgumentException` before sending; the API refused those requests anyway.
  - `RoutingManager.updateRoute(Route)`, and `assignDriver` and `assignVehicle`, which call it, reject a `null` route or a `null` or empty route ID with `IllegalArgumentException` before sending: `updateRoute` threw a `NullPointerException` for a `null` route, and sent a bare `route_id` for a missing ID.
  - `QueryConverter.convertObjectToParameters` leaves out `null` items of array and list fields; it threw a `NullPointerException`.
  - `RoutesRequest` gains `route_path_output` and `compress_path_points`; `Territory` gains `addresses_count` and `orders_count`; `TrackingHistory` gains its speed unit, member and source fields.
  - `TelematicsManager.createTelematicsConnection` and `updateTelematicsConnection` (V4) refuse a `TelematicsConnection` with a vendor API key (`apiKey`) with `IllegalArgumentException`, before sending: the V4 request carries the Route4Me key as the `api_key` query parameter, and the vendor key went as the `api_key` form field, so the API got two keys under one name. Use the new `createTelematicsConnectionV5` and `updateTelematicsConnectionV5`; on a V4 update, leave `apiKey` null to keep the stored key. A `null` connection also throws `IllegalArgumentException` (it threw `NullPointerException`).
  - `VehiclesManager.updateVehicle` rejects a `null` vehicle with `IllegalArgumentException` before sending; it threw a `NullPointerException`.
  - `GeocoderWebSockets` runs one job per instance: a second `startGeocoding` throws `IllegalStateException`, and a `null` or empty storage ID `IllegalArgumentException`. `getAddresses()` returns a copy, and an empty list instead of `null` before the job starts.
- **The V5 managers are new in this release** (they were never released before), so their request and reply classes follow the specs as they are now. Among the fixes made while covering the issues: vehicle, vehicle profile, capacity profile and team member updates use PATCH; `searchVehicles` posts its body; the address book list, batch update and export bodies, the order search, batch and archive bodies, and the customer `order_by` match the spec; barcode scans send `lng`; `schedule_blacklist` is a list of `{enabled, start, end}`; team bulk inserts go to `/team/bulk-insert` (the spec's `/team/users/bulk-insert` answers 405). Fixed after a local review of the stack:
  - The write methods of the V5 managers refuse a `null` request or body with `IllegalArgumentException` before sending, instead of sending the JSON text `null`. So do the methods that post a filter: `OrderManagerV5.searchOrders` and `archiveOrders`; `AddressBookManagerV5.getContacts`, `getContactsPaginated` and `getAddressBookContactsClustering` with a body request, and `exportAddresses`, `exportAddressesByAreas` and `exportAddressesByAreaIds`; `CustomerManager.getCustomersList`; `LocationManager.getLocationsCombined`, `getLocationsList`, `getLocationsClustering`, `getLocationsHeatmap`, `getLocationsTerritories`, `getLocationsExportColumns` and `exportLocations`; `VehiclesManagerV5.searchVehicles` and `SchedulesManager.getRouteScheduleCopies`. Pass an empty request for no filter. The GET forms (`getContacts`, `getContactsPaginated` and `getAddressBookContactsClustering` with a query, `TerritoriesManagerV5.getTerritories`) still read a `null` query as no query.
  - The address book also refuses `deleteContacts` or `getContactsByIds` with no IDs, `batchCreateContacts` with no contacts, `batchUpdateContacts` with no `address_ids`, and a delete or update by areas whose filter has neither a `selected_areas` entry with a `type` and a `value` nor a `bounding_box` with its four edges, since an empty filter could match every contact.
  - `VehicleV5` maps `external_telematics_vehicle_id` as text (`externalTelematicsVehicleId`); it mapped the plural, which the API does not have. Route destinations read `workflow_id` as text, `facility_id` as a number or a hex ID, facility `coordinates` as a `{lat, lng}` object, a `"lat,lng"` string or a `[lat, lng]` array (any other value, such as `false` or a number, as `null` instead of failing the reply), and a stop's skills under `required_skills` or `skills`.
  - IDs are `Long` where the API's are: `address_id`, `member_id`, `root_member_id`, `created_by_member_id` (locations, customers), `member_id` and `scheduled_for` (destination sorting), `note_id` and `address_id` (V5 notes). `order_by` fields are `List<List<String>>`, so equal requests are equal.
  - Lenient reads: `schedule_blacklist` also reads a single date string, `""` and nested arrays; `order_custom_field_type_info` reads an empty array (`[]`) as `null`.
  - `SchedulesManager.deleteRouteScheduleItems` returns `DeleteRouteScheduleItemsResponse`, which reads both `{status}` and the spec's `{data}`. The address book, address barcode and order managers return the shared `responses.StatusResponse`; their package copies are gone.
- **Booleans that the API sends as `1`/`0` are read correctly** (`LenientBooleanAdapter`, on every manager's JSON mapper). Gson rejected them, so a whole reply failed to parse, for example the vehicle profiles. Strings: a plain decimal number other than 0 (`"1"`, `"2"`, `"0.5"`) and `"true"`, `"yes"` and `"on"` (any case) are true; `""`, `"0"`, `"false"`, `"no"`, `"off"` and any other text, including other number notations such as `"1e3"`, are false, and a string never fails the parse. Every string 1.16.1 read as true still is.
- **`Map` fields read an empty JSON array as an empty map** (`LenientMapAdapterFactory`, on every manager's JSON mapper, in `AsyncJob.getBodyAs` and in `GeocoderWebSockets`). PHP sends an empty map as `[]`, for example `"EXT_FIELD_custom_data": []` on an order without custom data. `null` stays `null`, objects read as before, and a non-empty array now fails instead of being read as Gson's list of key and value pairs.

### Security
- **The API key goes only to `api.route4me.com` and `wh.route4me.com`, over https on port 443.** V4 requests send it as the `api_key` query parameter, V5 requests (`/modules/api/v5.0` and `v5.1`) as a bearer token. A request to any other host, or over another scheme or port, carries no key.
- The 11 deprecated `TelematicsManager` methods of the retired `telematics.route4me.com` host throw an `APIException` without sending a request. In 1.16.1 they sent the API key to that host.
- Redirects are followed only to `api.route4me.com` and `wh.route4me.com`. `rapid.route4me.com` and `validator.route4me.com` are no longer allowed: no SDK call goes there over HTTP, and Apache HttpClient copies the `Authorization` header onto a redirect.
- The unit-test request guard fails any request that carries the API key to another host, deprecated endpoints included, or that uses a port other than 443.
- No credentials in `toString()`: `User`, `AccountProfile`, `TelematicsConnection`, `Registration`, `UserRegistration`, `TeamMemberRequest`, `TelematicsMemberRegister` and `LocationCombinedDataItem` no longer print API keys, passwords, session IDs, activation keys or connection tokens. A test checks every model.
- The response body that `APIException` keeps hides credential members by the same name rule (`"password"`, `"connection_token"`, `"session_guid"`, any name ending in `api_key`, and so on), not only the manager's own key. When the message of an I/O failure quotes a URL with a credential (Apache HttpClient quotes the whole target of a refused or circular redirect), the exception keeps a redacted copy of the cause chain instead.
- `SECURITY.md` warns that Apache HttpClient's own DEBUG logging (`org.apache.http.headers`, `org.apache.http.wire`) prints the `Authorization` header and the `api_key` parameter.
- `APIException` and the logs redact credential query parameters by name (`api_key`, and any name ending in `api_key`, `apikey`, `_token`, `_secret` or `password`, such as `organization_api_key`). New utility class `utils.Sanitizer`.
- Dependencies: opencsv is removed (it brought old `commons-beanutils`); `log4j-api` 2.25.5, `gson` 2.14.0. `okhttp` 4.12.0 (with `okio` 3.6.0 and the Kotlin standard library) and `org.json` 20260814 are declared as direct dependencies, so Maven and Gradle projects that use the SDK resolve them instead of the vulnerable `okhttp` 3.12.12, `okio` 1.15.0 and `org.json` 20090211 that `socket.io-client` 1.0.2 asks for. osv-scanner reports no known vulnerability; one advisory for socket.io-client is ignored until 2027-04-30, with the reason in `osv-scanner.toml` (2.x cannot connect to `validator.route4me.com`).
- New `SECURITY.md`: how to report a vulnerability and which versions get fixes.
- `Manager` reads the hosts that receive the API key from `Route4MeRedirectStrategy.ALLOWED_HOSTS`, so the key hosts and the redirect hosts are one list and cannot drift apart. Every V5 URL is built by one `Manager.v5Builder`.
- `Links.toString()`, and so `DataObject.toString()`, hides `api_key` and the other credential query parameters of the `links` URLs; the getters still return the URLs unchanged.
- `RoutingManager.deleteRoutes` and `mergeRoutes` refuse a route ID that contains a comma, so one value cannot delete or merge more routes than the caller named.
- No path ID can reach the server as `%2F` or `%5C`: `Manager.withPathSegments` refuses an ID with `/` or `\` before sending, and the unit-test endpoint registry no longer matches an ID segment that holds either encoding.
- Telematics connection requests never carry two `api_key` values: the V4 connection methods refuse a vendor API key, and the new V5 ones send the Route4Me key as a bearer token and the vendor key as `vendor_api_key`.
- `GeocoderWebSockets` no longer logs the temporary storage ID, which selects the uploaded addresses.

### Added
- **API coverage (#42–#104).** 27 new managers and 247 new manager methods since 1.16.1, for the Route4Me API V4 and V5 operations the coverage issues list. Every request shape comes from the OpenAPI specs, then the C# SDK; the issues' own paths were often wrong. Each method has a unit test that pins its HTTP method, URL, query and body, and a runnable example.
  - New managers: `AccountProfileManager`, `AddressBarcodeManager`, `AddressBookManagerV5`, `AuthHistoryManager`, `AutocompleteManager`, `ConfigurationSettingsManager`, `ConfigurationSettingsManagerV5`, `CustomerManager`, `DistanceManager`, `DriverReviewManager`, `DriversManager`, `FacilityManager`, `FileUploadManager`, `LocationManager`, `NotesManagerV5`, `OptimizationProfileManager`, `OrderManagerV5`, `PodWorkflowManager`, `RouteCustomDataManager`, `RouteDestinationsManager`, `RouteStatusManager`, `RoutingManagerV5`, `SchedulesManager`, `TeamManagementManagerV5`, `TerritoriesManagerV5`, `TrackingHistoryManager` and `VehiclesManagerV5` (with vehicle and capacity profiles).
  - New methods on the 1.16.1 managers, for example `RoutingManager` (hybrid optimization, merge, share, mark departed and visited), `AddressBookManager` (groups, searches), `OrdersManager` (custom user fields, order updates), `TrackingManager` (device location history, user locations, batch pings, `findAsset`), `GeocodingManager` (batch geocoding), `UsersManager` (authentication, session validation) and `ActivityManager` (the activity feed).
  - Methods that start a background job return an `AsyncJob` with the job ID (from `X-Job-Id`, or from a `Location` that ends in `/job-tracker/status/{id}`, `/job-tracker/result/{id}` or any other `/status/{id}`), so the job status and result calls can follow it. They are the address book update, delete and export by areas, `deleteContacts` and the exports, `LocationManager.exportLocations`, the five vehicle bulk calls, `TeamManagementManagerV5.bulkCreateTeamMembers` and `TerritoriesManagerV5.createAutomaticTerritoriesJob`. Subclasses can use `Manager.makeJobRequest` for the same.
  - The address book exports answer `202` with only `Location: .../address-book/addresses/export/status/{id}`: follow them with the new `AddressBookManagerV5.getExportStatus(jobId)` (`GET .../export/status/{id}`, a JSON string) and download the file with `getExportResult(jobId)` (`GET .../export/result/{id}`), which returns its bytes unchanged, so `xls` and `xlsx` exports can be saved as they are.
- `TravelMode.BICYCLING` (#16), added after the 1.16.1 constants so their ordinals do not change; `RequestMethod.PATCH`.
- `RoutingManager.deleteRouteDestinations(long...)` (`POST /actions/route/delete_route_destination.php` with the form field `route_destination_id`, comma-separated, the name the API reads; the spec's `route_destination_ids` gets `409`).
- `Route`: the 15 fields C# has and Java lacked, such as `member_first_name`, `approved_for_execution` and `facility_ids`; `original_route` is typed as `Route`; new `BundledItem` (#17).
- `Address`: `required_skills` and 8 more fields from C#; new `OrderInventory` (#18).
- Telematics V5: `getTelematicsVendorsV5()`, `getTelematicsVendorsV5(TelematicsVendorsV5Request)`, `getTelematicsVendorV5(long)`, `createTelematicsConnectionV5(TelematicsConnection)` and `updateTelematicsConnectionV5(String, TelematicsConnection)` (`POST` and `PATCH .../v5.0/telematics/connections`, with the vendor key as `vendor_api_key`; the spec's `PATCH` is the partial update, while its `PUT` requires every field).
- `forwardGeocode(builder, clazz, maxAttempts)`. It retries no response, 408, 429 and server errors, not other client errors, which a retry cannot fix.
- `RouteDestinationsListResponse` maps `current_page_index` and `total_items_count`; `RouteStatusResponse` maps `resumed_at`; `GeocoderWebSockets.isStarted()` (`websocketsGeocoder` returns a geocoder that has not started when the address upload fails).
- For subclasses: `Manager.v5Builder(endpoint, segments...)`, `V5_BASE`, `requireRequest(request)`, which refuses a `null` request with `IllegalArgumentException`, and `makeRequest(..., byte[].class)`, which returns a response body unchanged.
- `Manager.getMaxResponseSize()` and `setMaxResponseSize(int)`, per manager like the timeouts, and `DEFAULT_MAX_RESPONSE_SIZE` (`Integer.MAX_VALUE - 8`, the largest Java array). A larger reply fails with an `APIException` instead of `OutOfMemoryError`: before its body is read when its `Content-Length` is larger, otherwise as soon as the bytes read pass the limit.
- `LenientBooleanAdapter.readString(String)`, the string rules of the adapter, for other lenient flag readers.

### Deprecated
- The 11 `TelematicsManager` methods on `telematics.route4me.com`, which is retired (it answers 301 to the marketing site), and `TELEMATICS_VENDORS_V4`. They throw an `APIException` without sending a request. Use the V5 vendor methods. Removal comes in the next major version.
- `RoutingManager.resequenceReoptimizeRoute` (`/api.v3/route/reoptimize_2.php`, `[Obsolete]` in C#): use `updateRoute(Route, RouteUpdateParameters)` with `reoptimize`. It is new in 2.0.0, added for C# parity and deprecated at once.
- Marked deprecated because the C# SDK marks the same calls `[Obsolete]`; they still work, and will be removed in the next major version:
  - `UsersManager` on `/api.v4/user.php`: `createUser` (use `TeamManagementManagerV5.createTeamMember`), `updateUser` (`updateTeamMember`), `getUser` (`getTeamMemberById`), `userDelete` (`deleteTeamMember`) and `getUsers()` (`getTeamMembers`). `getUsers(int, int)` (`view_users.php`), `userAuthentication`, `validateSession` and the other methods are not deprecated.
  - `AddressBookManager` on `/api.v4/address_book.php`: `getContacts` (use `AddressBookManagerV5.getContacts`), `createContact` (`addContact`), `updateContact` (`updateContact(long, AddressBookContactV5)`) and `deleteContact` (`deleteContacts`). `getContact`, `searchAddressBookLocation` and `searchAddressBookContactsByFilter` are not deprecated.
  - The whole `VehiclesManager` (the older `/modules/api/vehicles` API): `getVehicles`, `getVehicle`, `newVehicle`, `updateVehicle` and `deleteVehicle`. Use `VehiclesManagerV5`.
- Not added, with the reason in the issue comments: the rapid street-data service (404), the retired hosts `oa.route4me.com`, `telematics.route4me.com` and `apps.route4me.com/depots`, the obsolete route fallback endpoints (404), web-session calls, and endpoints that are not Route4Me's (Chamberlain MyQ, an OCR service over plain HTTP).

### Fixed
- #31 territory updates used DELETE. #32 busy-wait in `bulkGeocoder`. #33 quoted `address_id`. #34 `OrderRequest` field names. #35 unboxing NPE. #36 `DynamicInsertManager` NPE. #37 `return` in `finally`. #38 telematics searches delegated to the wrong method. #39 `setGPS` (it already used query parameters; it now returns the reply). #40 mutable enums. #41 trailing comma in `deleteRoutes`.
- `Constants.DeviceType` and `OptimizationParameters` serialise with their API names.
- `bulkGeocoder` keeps the latitude and longitude of a match that comes without `coordinates`; they were overwritten with 0.
- `NotesManager.addCustomNoteType` sends `type` and `values`, as the C# and PHP SDKs do, and requires at least one value; the API answered `400` ("Field values is required") to the spec's `note_custom_type` and `note_custom_type_values`.
- `GeocoderWebSockets` unsubscribes from `addresses_bulk` on close, and sizes its download chunks from the job size.
- `TelematicsManager.getTelematicsConnections` returns `TelematicsConnection` objects. It returned Gson maps typed as `List<TelematicsConnection>`, so reading an element threw `ClassCastException`; code that cast the elements to `Map` must drop the cast.
- `TelematicsConnection.metadata` is sent as the text of a JSON object, as the telematics API reads it; it went as `Map.toString()` (`{key=value}`). `is_enabled` is read leniently (`1`, `0`, `1.0`, `"yes"`, `""`) instead of failing the reply, and whole numbers in `metadata` stay `Long`, so metadata read and sent back keeps `12345` (it became `12345.0`). `TelematicsVendorCredentials` reads the credential default from `default`, the name in the spec; it mapped the typo `defaut`, which is still read.
- `GeocoderWebSockets` can be polled from another thread: its state is guarded by a lock. Its Socket.IO handlers ignore an empty or unreadable message instead of throwing on the event thread, it counts an `address` message without an address so the job completes, and it sends its `geocode` request once per job, so a Socket.IO reconnect no longer geocodes the batch again. `websocketsGeocoder` treats an empty storage ID like a missing one.
- `bulkGeocoder` caps `maxTimeout` times the number of rounds at `Long.MAX_VALUE`; a very large timeout wrapped to a negative wait and cancelled every address. `GeocodingManager`, `GeocoderWebSockets` and `TerritoriesManager` log through Log4j 2 only.
- `TerritoriesManager.getPolygonsFromTerritories` skips, with a warning, a territory with a malformed polygon point instead of failing and returning no polygons. `NotesManager.getAllCustomNoteTypes` throws `APIException`, not Gson's unchecked `JsonSyntaxException`, when an item cannot be read.
- `DriverReviewManager.createDriverReview` and `updateDriverReview` reject a `null` review before sending; `DriverReviewSettingsRequest.toString()` leaves out the Base64 logo. `FileUploadManager` holds one copy of the file in the multipart body instead of three, and refuses a body larger than `Integer.MAX_VALUE - 8` bytes with `IllegalArgumentException` instead of `OutOfMemoryError`.
- A request whose manager is closed while it reads the reply fails with "the manager was closed while the request ran", like one waiting for a connection, instead of "Socket closed". `Manager.setCallBackURL` reaches requests on other threads.
- An error body that quotes a URL with a credential keeps its `errors`, `messages` and `code`: `Sanitizer.redactUrl` ends the hidden value at whitespace, `"`, `<` or `>` too, instead of hiding the rest of the body.
- Javadoc: the timeout and memory limits of `FileUploadManager.uploadFileGeocode`, `TrackingHistoryManager.exportTrackingHistory` and `RoutingManagerV5.exportRoute`, the values of `GPSPosition.format`, `RouteStatusRequest.reason`, and the `IllegalArgumentException` of the methods that throw it.

### Examples
- The examples moved from `src/main/java` to `src/examples/java` and compile with every build. They are no longer in the jar: the `com.route4me.sdk.examples` classes that the 1.16.x jars contained are gone. Each has a class comment saying what it shows and which method it calls, and reads the key from `R4M_API_KEY`. They call the live API, so run them against a test account. The examples that change or delete existing data, and the ones that need an ID from the caller's account, take their targets from their arguments or from environment variables such as `ROUTE_ID`, `ROUTE_DESTINATION_ID`, `ORDER_ID`, `VEHICLE_ID` or `MEMBER_ID`, and stop when they are not set; each class comment names the variables it reads. They no longer pick the newest route or the first route, optimization, territory, contact, order or stop, and send no hard-coded IDs and no placeholders such as `ROUTE_ID_HERE` or `ORDER_ID_1`; `BatchUpdateFilterV5` recolours only the orders in `ORDER_IDS`. A malformed value (an ID that is not a number, an empty list item, an inverted bounding box, a bad date) stops the example with a message (`ExampleInput` in `examples/utils`). Passwords, session IDs, tokens and telematics credentials come from environment variables too, the contact data is fake (`example.com`, `555` numbers), and the configuration key examples use the throwaway key `sdk_example_key`.
- The examples stop with a message instead of failing later: the advanced-constraint examples when they cannot read `locations.csv` or `schedules.csv` (they sent an empty optimization), the route searches after a failed search, and the file upload examples without their arguments. The optimization examples print a missing state instead of throwing. `WebSocketsGeocoderExample` gives up after 5 minutes, the export examples poll `getExportStatus` until it reports done and then download the file once (`GetExportResultV5` saves it to `EXPORT_FILE`), and `GenericExample` closes its manager.
- 370 runnable examples, one for each new method, plus the `CsvRows` helper; the example issues (#105–#109) each get theirs. The examples of deprecated methods whose V5 replacement had no example now show the replacement (`DeleteUser`, `CreateAddressBookContact`, `UpdateAddressBookContact`, `GetVehicle`, `DeleteVehicle`); the others still show the deprecated method and name the V5 example to use.

### Internal
- 871 offline unit tests (there were none in the repo): every request is checked against an endpoint registry built from the Route4Me OpenAPI specs, with the host, the scheme and the key placement. Where an endpoint has method-specific entries, only those methods pass: an any-method entry no longer hides a wrong method. JaCoCo enforces a coverage floor.
- The unit tests fail closed: a connection to any host but the loopback address fails the test (a default `ProxySelector` that the surefire listener and `MockHttp` install), so a manager a test forgot to mock, or the WebSocket geocoder, cannot reach the network. The key check also reads the SDK's Log4j 2 events at every level and its `java.util.logging` records down to `FINE`, `MockHttp` accepts only managers built with its placeholder key, and a guard failure is reported even when the test is then skipped.
- The test harness routes every `HttpClient.execute` overload that takes an `HttpUriRequest` through the request guard, and fails a test that calls any other overload, even when the code catches the error. The guard rejects user information in URLs and dot segments in place of IDs, `assertJson` checks JSON types, the network block lets only loopback literals through, and the endpoint registry no longer has the 35 generator artifacts that matched almost any path on `wh.route4me.com`. `ApiKeyExposureTest` checks `toString()` of every SDK class with a credential-like field, found by a scan of the compiled classes, and fails on a class it cannot load. A test that passes an `HttpContext` to the mocked client fails, since the guard cannot see the credentials or proxy a context adds.
- Checkstyle 9.3 with zero violations, `javac -Xlint:all -Werror`, and Javadoc doclint on every build. Every public type, method and field has Javadoc.
- CI: JDK 8, 11, 17 and 21; Actions pinned to commit SHAs; `permissions: contents: read`; a gitleaks job. The Travis config is removed.
